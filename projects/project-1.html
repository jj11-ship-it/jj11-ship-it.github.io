项目背景与问题

核心问题

校园办事规则分散在官网、PDF 与公众号等多个来源，新旧版本并存且互相矛盾；学生照着过期或错误的信息办事，会付出带错材料、去错地点这类实际代价。

关键挑战

既要让 AI 把分散资料整理成可执行、可追溯的答案，又不能让它越过证据编造——查不到依据必须明说；同时要应对规则年度更新带来的版本冲突，以及代办类需求的安全边界。

产品目标：把“搜到什么信什么”的办事信息获取，转化为带官方引用、可勾选执行、证据不足明确拒答的可信办事流程。

关键产品决策

01

可信优先于回答率

证据不足明确拒答、每条回答带引用；用户会照着答案办事，编造的答案比承认不知道危害大得多。

02

否决 Hybrid Search 上线

对照实验让 55 题 Top-3 从 98.18% 退化到 92.73%，按预设回归关口否决：不是所有“更先进”都该上，每个组件上线前必须回答“解决了哪个稳定复现的问题、带来多少收益”。

03

不上 reranker

排序问题（报到材料分块稳定排第 8）用 metadata 软加权最小修复，chunk 从第 8 名进 Top-2；收益已被最小方案覆盖，重武器省了。

04

主评测不用 LLM-as-Judge

16 题人工终审成本约 2 小时，Judge 的校准成本反而更高；后用独立 LLM 复核做了评分一致性检验（判定一致 5/5、±1 一致 100%），作为引入 Judge 前的校准步骤。

PRD 摘要

01

用户与核心场景

目标用户：需要在报到期集中办理多项事务的高校新生，以及有偶发校园服务需求的在校生。

核心场景：快速确认“带什么、去哪办、按什么规则”，获得来源可查、可以直接执行的办事清单。

需求边界：聚焦官方信息整合、引用与任务规划；不接入校内私有系统、不读取个人隐私、不代替用户办理事务。

02

核心业务流程

流程 1：RAG 问答链路

提问 → 检索 → 上下文组装 → 生成 → 引用展示 → 证据不足拒答

流程 2：Agent 办事流程

输入需求 → 多域检索 → 校区过滤 → 生成草稿 → 证据补查与逐字回填 → 引用剪枝 → 确定性校验 → 用户确认 → 保存与状态管理
03

产品范围与优先级规划

  • 风险优先于广度：最高风险假设最先验证：先证明“AI 不编造”，再扩展场景。
  • 测量先于扩展：评测体系建在功能扩展之前：没有度量，迭代就是拍脑袋。
  • 场景推导形态：信息查询做问答、多步骤任务做 Agent：产品形态由用户任务决定，不由技术决定。
  • 门槛纪律：每个新组件上线前必须回答“解决了哪个稳定复现的问题、带来多少收益”，未达门槛不做。
04

核心功能需求

  1. 可信办事问答：基于官方资料生成带引用的回答；证据不足时明确拒答，并引导用户前往官方渠道。
  2. 新生办事台：将多项需求整理为带引用的任务清单，经用户确认后保存，并支持状态跟踪与重新规划。
  3. 澄清追问：需求模糊时只追问最关键的缺失条件；不索取敏感信息，无法确认时拒绝推测并提供替代指引。
05

核心验收标准

  • 每条回答必须关联至少一条可展开核验的知识库原始证据（引用）。
  • 依据不足时必须明确说明“没有找到充分依据”并指引官方渠道，不得编造或推测。
  • 废止与草稿资料不得参与回答；回答与证据冲突时以证据为准。
  • 高风险事务强制引用、证据不足即拒答分流；紧急风险不做常规问答、直接引导人工渠道。

AI 能力边界与评测

能力边界

  1. 生成不等于判定

    AI 只生成回答与任务草稿；校区、引用和证据由确定性规则校验，最终评测由规则与人工完成。

  2. 无证据，不回答

    回答必须来自有效官方资料；证据不足或涉及高风险事务时明确拒答，并引导至人工或官方渠道。

  3. 不代办，不越权

    系统只负责检索、规划与保存，不收集支付凭证等敏感信息，也不代替用户执行对外操作；写入前必须由用户确认。

评测指标

  • Top-3 检索命中率（Hit Rate@3）
  • 平均倒数排名（MRR）
  • 引用支持率（Citation Support Rate）
  • 拒答准确率（Refusal Accuracy）
  • Agent 任务质量评分（Agent Rubric Score）
  • 执行轨迹合规率（Trajectory Compliance Rate）

交付物与复盘

主要交付物

  • 可信问答与引用机制
  • 知识库治理与分块策略
  • 三层评测体系与双轨复核
  • 归因迭代方法论

复盘

可信是产品功能，不是技术约束拒答、引用、风险分级和确认机制都是产品功能；可信不是在 Prompt 里写一句“不要幻觉”，而是一套完整的产品机制。

先分清产品失败还是评测失败评测口径错误会让所有指标失真；先校准口径，再修系统。

AI 的边界靠确定性兜底，不靠模型自觉Prompt 规则可能被模型遗忘，代码级校验节点不会；修复应从“改提示词”升级为“建立确定性防线”。
